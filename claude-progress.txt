## 状況: 完了
iOS と Android の両方の実機で、本番の Web と Go にインターネットで繋いで、登録、編集、Google の連携、退会を確認した。実行中のタスクはない。

## できること(すべて main)
- メールのログイン(マジックリンク)とログアウト。ログイン CSRF の防御と、1 回限りのコード + PKCE。判断は src/lib/sign-in-rules.ts
- プロフィールの閲覧と編集(name は Web、bio は Go)
- 退会(メールの再入力。5 分以内のログインが要る)
- Google の連携と解除(プロフィール画面)、Google でのサインイン(ログイン画面。連携済みのユーザーだけ)

## 実機に入れる
- 本番の URL をビルド時に埋め込む(EXPO_PUBLIC_WEB_URL と EXPO_PUBLIC_API_URL。https)。Metro も adb reverse も要らない
- Android: `npx expo run:android --device --variant release`(USB デバッグをオン)
- iPhone: `npx expo run:ios --device --configuration Release`(無料の署名。7 日で期限が切れるので入れ直す)
- app.json を変えたら ios/ と android/ を消して作り直す
- 本番の DB は別なので、Google は本番でも連携し直す。Render の無料プランは、スリープ明けの最初の bio が出ない(Reload)

## 既知の限界
- 攻撃者のアプリが端末にある場合、コードを取られうる(Universal Links / App Links が要る)
- 画面のテストはない(判断のロジックだけ)。ストアには出さない
- 開発中の Android は、Web が localhost で `adb reverse tcp:3000 tcp:3000` が要る(Go は 10.0.2.2)
- Web の /api/auth/expo-authorization-proxy の open redirect とログイン CSRF は、Web で修正済み(Web の PR 28、29)。モバイルの Google は、同じ入口を通る
