## 完了したタスク
- スパイク(使い捨て。ブランチ spike/auth-flow、Web 側は spike/expo-auth。どちらも push 済み、main には入っていない)
  - 確かめたこと: マジックリンク → ディープリンクでアプリに戻る → セッションを SecureStore に保存 → GET /api/auth/token に Bearer で JWT → Go の GET /me。iOS と Android の両方で /me まで通った
  - 分かったこと: Android エミュレータは localhost が自分自身(Mac は 10.0.2.2、メールのリンクは adb reverse tcp:3000 tcp:3000)。iOS 27 のシミュレータは scene 非対応のアプリを落とす(SDK 58 のテンプレートで直る)。Android 16 以降はローカルネットワークの許可を聞かれる(拒否すると接続できない)。CocoaPods が要る
- 土台(PR #1、main に入った): Expo SDK 58、テンプレートの削除、hooks と evaluator、CI(lint、tsc、expo export)、CLAUDE.md、このファイル
- Web 側の Expo 対応(feature/expo-native-client。push 済みで CI を実行した。main に入ったかはこのファイルでは未確認)
- Web の guard-pre.sh の any 検出を直した(Web の PR #21、main に入った)
- 認証(ブランチ feature/auth-flow。main から)
  - src/lib: config(接続先。リリースビルドは https の URL が必須)、auth-client、sign-in-link(送信時に state を作って保存し、戻ってきたリンクの state と照合。形の検証、使い切り、10 分の期限)、token(JWT を毎回取る。保存しない)、api(GET と PUT の /me/profile。画面はまだ使っていない)
  - 画面: _layout(ログイン状態で sign-in と index を出し分け。ディープリンクの受け取り)、sign-in(メールの入力と送信)、index(最小のホーム。メールの表示とログアウト)
  - +native-intent.ts: リンクの Cookie をルーターのパラメータに残さない(端末で確認済み)
  - better-auth と @better-auth/expo は Web と同じ 1.7.7 に固定
- 端末での確認(iOS シミュレータと Android エミュレータ): ログイン、ログアウト、コールドスタート(アプリを終了してからリンクで起動)でログインできる。偽のリンク(state が違う)は、iOS と Android の両方で拒否される(iOS は送信の前後とも確認)
