## 既知の限界(許容している)
- 実機は未確認(シミュレータとエミュレータのみ)
- 本番の Universal Links / App Links は未対応(今は betterauthmulti:// のカスタムスキームだけ)。他のアプリが同じスキームを登録すると、本物のリンクの Cookie を読める(Web の docs/design.md にも書いてある)。本番は Universal Links / App Links か、1 回限りのコード交換にする
- Google ログインのリンク(モバイルから)は未対応
- 画面のテストはない(判断のロジックは sign-in-rules.ts のテストで守っている)。evaluator と CI は、端末での動作とネイティブのビルドを確認できない
- 未使用の依存が残っている(@expo/ui、expo-device、expo-network、expo-glass-effect、expo-symbols、expo-constants など。雛形の名残に見える)。ネイティブ依存の削除は、再ビルドと両 OS の確認が要るので、別の PR にする(app.json の plugins が使うもの: expo-font、expo-image、expo-status-bar、expo-web-browser、expo-splash-screen は、plugin ごと見直す)
- ログイン中に不一致のリンクが開かれても、「Sign-in failed」のアラートが出る(見た目だけ。安全には影響しない)
- app.json の name と slug が雛形のまま
- 最新の送信だけが有効(連続で送ると、前のリンクは使えなくなる)
- **本番の前に必須(レビューの S3)**: カスタムスキーム(betterauthmulti://)は他のアプリも登録できる。さらに Web の本番の trustedOrigins が無条件にこのスキームを含むので、モバイルを使わない人のメール宛てにも、攻撃者が callbackURL 付きのリンクを送らせられる。本番に出す前に、1 回限りのコード交換(Cookie を URL に載せない。短命のコードを、アプリが verifier 付きで引き換える)にする。Universal Links / App Links にする場合も、セッションを URL に載せない形にする
- app.json の com.anonymous.mobile は雛形のまま。本番の前に変える(ストア審査と App Links の設定で詰まる)
- APP_SCHEME と STORAGE_PREFIX が config.ts と app.json に二重定義(コメントで同期を促しているだけ)。app.config.ts から読むほうが安全
- 開発中は、Android エミュレータでマジックリンクを開くのに adb reverse tcp:3000 tcp:3000 が要る(エミュレータの再起動で消える)

   - ログインから 5 分を過ぎると 403(recent sign-in required)になる。api.ts は 401 しか区別していないので、403 を「もう一度ログインして」の導線にする
   - Web の /token の HTTP 拒否の見直し
4. 退会後の復活の窓(Go の PUT /me/profile が、退会後 5 分以内の古い JWT で行を作り直す)は、Go 側で閉じる(Go の進捗ファイルに書いてある)
5. 未使用の依存を外す(上の限界を参照)
